# 天气与地理数据

观晴的正式界面直接调用 Open-Meteo 免费公共接口，不需要 API Key。生产代码没有模拟天气，也不会在请求失败后生成天气数字。坐标、当前天气、24 小时预报和 7 天天气均来自真实接口；测试中的固定样本仅用于自动化验证。

## Weather MCP 调研与适配选择

已核实用户指定的 [Weather MCP 项目](https://github.com/weather-mcp/weather-mcp)。其官方 npm 包为 `@dangahagan/weather-mcp`（调研时为 `1.33.20`），全球天气来源同样是 Open-Meteo。其 `get_forecast`、`get_current_conditions` 可供对话工具复用，具备天气之外的广泛能力。

该项目是完整独立 MCP 服务器，包入口启动服务，并非稳定的天气 SDK。内部 `OpenMeteoService` 提供原始字段，但需要非公开深层导入，默认将当前天气和预报拆成两次查询、预报缓存 2 小时。首版界面需要统一的当前 / 小时 / 日数据、精确 epoch 时间和 10 分钟缓存，因此采用 [Open-Meteo 官方 Forecast API](https://open-meteo.com/en/docs) 的单次结构化查询作为轻量适配层，避免绑定内部 API。Atmos 自身的 MCP 工具与界面共用这个服务，不解析上游自然语言回答。未来接入 Weather MCP 时可替换 `getWeather` 的上游实现而不改 UI。

## 字段、时间、来源

- `current`：温度、体感、天气代码、湿度、风速、风向、降水量、云量、昼夜标识。
- `hourly`：从当前小时起共 24 个时段，温度、天气、降水概率、昼夜、UV；使用至少 7 天的原始时间轴，避免傍晚只能拿到今天剩余几小时。
- `daily`：当地今天起 7 天，最高 / 最低温、天气、最大降水概率、日出 / 日落、最大 UV。
- Open-Meteo 请求 `timeformat=unixtime`，服务端统一将秒转换为毫秒。前端用返回的城市 IANA 时区格式化，杜绝宿主时区泄漏和夏令时重复小时丢失。日出 / 日落始终保留绝对时间。
- 温度存为 °C，风速 km/h，降水 mm；华氏换算在显示层完成。
- 缺失数字保留 `null`，未知天气代码为 `-1`；不会把缺失温度当成 0°C，也不会把未知天气当成晴。
- 摘要从未来 12 小时的代码、概率与时间确定性生成，不编造降雨、转晴或体感描述。
- `current.time` 是数据有效时间，`fetchedAt` 是实际取得数据的时间；二者不同。当前天气属于模型估计，15 分钟时间步不等于气象站实时观测；部分区域由小时数据插值。上游模型按各自周期更新。

## 缓存、限流与错误

缓存以坐标和时区为键，TTL 10 分钟，最多 256 个位置；同一位置进行中的请求合并。手动刷新最短间隔 60 秒。一次刷新是一次 Open-Meteo 请求；每进程限制最多 30 次 / 分钟、1,500 次 / 24 小时，最多 8 个同时请求。城市查询另限制 30 次 / 分钟、1,000 次 / 24 小时。网络超时 12 秒，不进行无界重试。

请求失败时可以返回不足 24 小时的已有天气，并标记 `cached=true, stale=true`，保留真实的原始刷新时间；没有缓存时返回简洁的中文错误及重试入口。超过 24 小时不再作为当前天气展示。服务端缓存存在于本地服务进程内，不记录定位历史；浏览器会在本机保存用户选择、收藏与最近天气，供恢复和离线显示。

Open-Meteo 免费服务仅限非商业使用，官方限额为每分钟少于 600 次、每小时少于 5,000 次、每天少于 10,000 次；数据采用 CC BY 4.0 并须署名。应用的更低限额面向个人本地使用，多进程或公开部署需共享限流、评估许可和上游配额。[官方条款](https://open-meteo.com/en/terms)

## 城市搜索与当前位置

精选城市支持中英文名称和常见别名；其他城市调用 [Open-Meteo Geocoding](https://open-meteo.com/en/docs/geocoding-api)，保存 `geonames:<id>`、经纬度、国家、一级行政区和 IANA 时区。按距离与名称双重校验精选素材匹配，不因同名城市误用背景。搜索结果缓存一天。

定位仅由用户点击后触发。服务端将经纬度发给 [OpenStreetMap Nominatim 反向地理编码](https://nominatim.org/release-docs/latest/api/Reverse/)，返回城市名称；接口按每秒最多一次串行调用，带应用 User-Agent，并缓存一天。Nominatim 不可用时使用 [Photon / Komoot](https://github.com/komoot/photon) 的公共反向地理接口，读取实际 `city` 字段，不把附近商店或其他 POI 名称当成城市。失败的 Nominatim 暂停访问 5 分钟以避免持续等待。两者都只用于用户触发的反向定位，不用于自动补全。均无法解析时保留原始坐标，显示“当前位置”，继续查询真实天气。时区使用 `tz-lookup` 依据原始坐标解析，不以浏览器时区猜测。原始坐标不会被替换为市中心坐标。

地名数据来源 GeoNames；反向地理信息来源 © OpenStreetMap contributors（ODbL）。[Nominatim 使用政策](https://operations.osmfoundation.org/policies/nominatim/)

此首版只面向个人本地天气查询。Nominatim 公共服务不适合作为通用地理编码平台、自动补全或批量检索。可通过服务端 `ATMOS_REVERSE_GEOCODING_URL` 与 `ATMOS_PHOTON_REVERSE_URL` 切换兼容的反向查询端点，无需更新前端；公开或多实例部署前，应改用自己的服务或其他适用提供方，并遵守整个应用每秒一次的总限制。Photon 官方允许合理请求量的小型项目使用其演示接口，可能限流且不保证可用；本应用同样受缓存及限流保护。

## 验证

`npm test` 包含时间转换、跨夏令时重复小时、缺失值、预测摘要、请求去重、强制刷新、缓存过期、离线回退、同名城市和反向地理失败等测试。

`npx tsx tests/weather-live.ts` 对 10 个精选城市逐一调用正式适配器，检查来源、城市时区、24 个小时与 7 个日预报。输出是实时测试记录，不作为应用数据源。
